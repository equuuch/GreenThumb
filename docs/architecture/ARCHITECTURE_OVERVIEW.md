# Архитектурный обзор системы (Architecture Overview)

Настоящий документ описывает высокоуровневую архитектуру проекта GreenThumb, обосновывает выбор ключевых паттернов проектирования и объясняет логику взаимодействия компонентов системы

## 1. Архитектурный паттерн: Service Layer (Модульная монолитность)

В проекте реализовано четкое разделение ответственности между слоем хранения данных и слоем представления

* **Data Access Layer (DAL)**: использование SQLAlchemy 2.0 для изоляции SQL-запросов и обеспечения типобезопасности моделей
* **Business Logic Layer (BLL)**: вынос всей логики в независимые сервисы (Auth, Plant, Care, AI). это позволяет тестировать бэкенд без участия интерфейса
* **Presentation Layer**: реактивный интерфейс на Flet, который является «тонким клиентом» и только отображает данные, полученные из сервисов

## 2. Стратегия управления данными

Система спроектирована по принципу Offline-First для обеспечения стабильной работы в условиях нестабильного интернет-соединения

* **SQLite**: выбор в пользу встраиваемой базы данных позволяет хранить всю информацию локально на устройстве пользователя
* **Атомарные транзакции**: использование блоков try-except-rollback в сервисах гарантирует, что данные не будут повреждены при частичном сбое
* **Нормализация справочника**: разделение пользовательских данных и глобального каталога исключает дублирование эталонной информации о видах растений

## 3. Интеллектуальный модуль и оптимизация ресурсов

Логика взаимодействия с GigaChat API построена на принципе максимальной экономической эффективности (Token Saving)

* **Оркестрация моделей**: автоматическое переключение между моделью Lite для текстовой генерации и моделью Max для визуальной диагностики
* **Image Processing Pipeline**: предварительная обработка изображений через Pillow (ресайз до 1024px и сжатие JPEG). это сокращает расход токенов на 60–80% за счет оптимизации количества анализируемых патчей
* **Кэширование токенов**: хранение OAuth-токена в памяти процесса на 30 минут для минимизации лишних сетевых запросов

## 4. Система автоматизированного планирования

Реализован механизм «Бесконечного цикла ухода», который минимизирует когнитивную нагрузку на пользователя

* **Trigger-based planning**: создание новой задачи в календаре происходит автоматически в момент закрытия предыдущей
* **Динамические интервалы**: расчет дат производится на основе метаданных из глобального каталога, адаптированных под конкретный экземпляр растения

## 5. Безопасность и экспорт данных

* **Криптографическая защита**: использование алгоритма scrypt для одностороннего хеширования паролей пользователей
* **Бинарная генерация отчетности**: прямой программный рендеринг PDF-документов через ReportLab, что обеспечивает независимость от браузерных движков и высокую точность верстки
