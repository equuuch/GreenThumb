# DATABASE_SCHEMA.md

Детальное описание реляционной модели данных проекта GreenThumb, реализованной на базе SQLite с использованием SQLAlchemy 2.0.

## 1. Архитектурные принципы хранения

* **Целостность данных**: использование внешних ключей (ForeignKey) и каскадного удаления (`ON DELETE CASCADE`) для всех зависимых сущностей.
* **Нормализация справочника**: разделение эталонных ботанических характеристик (`plant_catalog`) и пользовательских экземпляров растений (`plants`).
* **Атомарность**: выполнение всех операций в рамках транзакций с автоматическим откатом (rollback) при сбоях.

## 2. Описание таблиц

### 2.1. Таблица users
Хранит данные учетных записей пользователей.
* **user_id**: первичный ключ, автоинкремент.
* **email**: уникальный адрес почты (используется как логин).
* **password_hash**: строка, содержащая пароль или его хеш.
* **first_name**: имя для персонализации интерфейса.
* **created_at**: метка времени регистрации.

### 2.2. Таблица plant_catalog
Глобальный справочник видов растений.
* **catalog_id**: первичный ключ.
* **species_name**: уникальное официальное название на русском языке.
* **latin_name**: научное название на латыни.
* **description**: текстовое описание характеристик и советов по уходу.
* **default_watering_interval**: базовый интервал полива в днях.
* **default_light_level**: рекомендуемый уровень освещенности (от 0.1 до 1.0).

### 2.3. Таблица plant_aliases
Система сопоставления народных или сокращенных названий с каталогом.
* **alias_id**: первичный ключ.
* **user_input**: вариант названия в нижнем регистре (индексируемое поле).
* **catalog_id**: ссылка на основной вид в справочнике.

### 2.4. Таблица plants
Конкретные экземпляры растений, принадлежащие пользователям.
* **plant_id**: первичный ключ.
* **user_id**: идентификатор владельца.
* **catalog_id**: ссылка на вид в справочнике (может быть пустой для неопознанных видов).
* **custom_name**: домашнее имя растения (например, «Фикус на окне»).
* **image_url**: относительный путь к фотографии в папке `assets/plants/`.
* **status_text**: краткая информация о состоянии (последний замер роста).
* **last_watered_at**: дата и время последнего фактически подтвержденного полива.
* **user_light_level**: персональная настройка освещенности для коррекции графиков.
* **is_active**: логический флаг (True — активно, False — в архиве).

### 2.5. Таблица care_calendar
Планировщик и история выполнения процедур.
* **calendar_id**: первичный ключ.
* **plant_id**: ссылка на целевое растение.
* **task_type**: тип задачи (например, «watering»).
* **scheduled_date**: дата, на которую запланировано выполнение.
* **completion_date**: фактическое время закрытия задачи.
* **is_completed**: флаг завершения задачи.

### 2.6. Таблица growth_logs
Хронология физического развития растения.
* **log_id**: первичный ключ.
* **plant_id**: ссылка на растение.
* **height**: числовое значение роста в сантиметрах.
* **note**: текстовый комментарий пользователя к замеру.
* **image_path**: путь к фотографии, фиксирующей прогресс на дату замера.
* **measured_at**: дата проведения физического замера.

### 2.7. Таблица ai_consultations
Архив взаимодействий с интеллектуальным ассистентом.
* **consultation_id**: первичный ключ.
* **user_id**: идентификатор пользователя.
* **plant_id**: ссылка на растение (контекст вопроса).
* **prompt_text**: текст вопроса пользователя или системного запроса.
* **response_text**: полный ответ модели GigaChat.
* **consultation_type**: категория запроса (advice, diagnosis, passport).

### 2.8. Таблица token_usage
Система учета потребления вычислительных ресурсов API.
* **token_usage_id**: первичный ключ.
* **user_id**: идентификатор пользователя.
* **tokens_count**: количество затраченных токенов за операцию.
* **request_type**: технический тип запроса для статистики.

## 3. Логика связей

* **User к Plants**: связь «один ко многим». При удалении пользователя удаляются все его растения и связанные с ними данные.
* **Plant к CareCalendar/GrowthLogs**: связь «один ко многим». Удаление или архивация растения управляет состоянием его задач.
* **Plant к AIConsultations**: история переписки сохраняется даже после удаления растения, если поле `plant_id` не было очищено вручную, либо удаляется каскадно.
