# Спецификация структуры базы данных (Database Schema)

Настоящий документ содержит детальное описание реляционной модели данных проекта GreenThumb. База данных спроектирована с использованием SQLAlchemy 2.0 и реализована на движке SQLite

## 1. Архитектурные принципы хранения

* **Целостность данных**: использование внешних ключей (ForeignKey) и каскадного удаления (CASCADE DELETE) для предотвращения появления ошибок в связях
* **Нормализация**: разделение эталонных ботанических данных (Catalog) и пользовательских экземпляров (Plants)
* **Аудит ресурсов**: логирование каждого запроса к ИИ для контроля расхода токенов и анализа активности

## 2. Описание таблиц

### 2.1. Таблица users
Хранит данные учетных записей пользователей.

* **user_id**: первичный ключ, автоинкремент
* **email**: уникальный адрес почты для авторизации
* **password_hash**: безопасный хеш пароля, сгенерированный алгоритмом scrypt
* **first_name**: имя пользователя для отображения в интерфейсе
* **created_at**: дата и время автоматической регистрации записи

### 2.2. Таблица plant_catalog
Глобальный справочник растений с эталонными характеристиками.

* **catalog_id**: первичный ключ
* **species_name**: уникальное официальное название на русском языке
* **latin_name**: научное название растения на латыни
* **description**: краткое ботаническое описание вида
* **default_watering_interval**: базовый интервал полива в днях
* **default_light_level**: рекомендуемый уровень освещенности от 0.1 до 1.0

### 2.3. Таблица plant_aliases
Система нормализации названий для сопоставления народных имен с каталогом.

* **alias_id**: первичный ключ
* **user_input**: вариант названия в нижнем регистре
* **catalog_id**: внешний ключ к основной таблице справочника

### 2.4. Таблица plants
Экземпляры растений, принадлежащие конкретным пользователям.

* **plant_id**: первичный ключ
* **user_id**: идентификатор владельца (внешний ключ к users)
* **catalog_id**: ссылка на вид в справочнике (внешний ключ к plant_catalog)
* **custom_name**: имя, данное растению пользователем
* **image_url**: относительный путь к локальному файлу фотографии
* **status_text**: текстовый статус состояния здоровья растения
* **last_watered_at**: дата и время последнего зафиксированного полива
* **added_at**: дата добавления растения в коллекцию пользователя

### 2.5. Таблица care_calendar
Планировщик задач и история выполнения процедур по уходу.

* **calendar_id**: первичный ключ
* **plant_id**: ссылка на целевое растение (внешний ключ к plants)
* **task_type**: тип задачи, например watering
* **scheduled_date**: дата, на которую запланировано выполнение
* **completion_date**: фактическое время завершения задачи
* **is_completed**: логический флаг состояния задачи

### 2.6. Таблица growth_logs
Журнал физических параметров для мониторинга динамики развития.

* **log_id**: первичный ключ
* **plant_id**: ссылка на растение (внешний ключ к plants)
* **height**: высота растения в сантиметрах
* **note**: текстовое примечание пользователя к замеру
* **image_path**: путь к фотографии, фиксирующей прогресс
* **measured_at**: дата проведения физического замера

### 2.7. Таблица token_usage
Система учета потребления вычислительных ресурсов ИИ GigaChat.

* **token_usage_id**: первичный ключ
* **user_id**: идентификатор пользователя (внешний ключ к users)
* **tokens_count**: количество потраченных токенов за одну операцию
* **request_type**: категория запроса, например passport или diagnosis

### 2.8. Таблица ai_consultations
Архив истории взаимодействий пользователя с интеллектуальным ассистентом.

* **consultation_id**: первичный ключ
* **user_id**: ссылка на пользователя (внешний ключ к users)
* **plant_id**: ссылка на контекстное растение, может быть пустым
* **prompt_text**: исходный текст вопроса пользователя
* **response_text**: полный ответ, полученный от модели ИИ
* **consultation_type**: технический тип промпта для фильтрации

## 3. Логика связей

1. **User к Plants**: связь один ко многим, один пользователь владеет садом
2. **PlantCatalog к Plants**: связь один ко многим, эталонный вид может быть у многих людей
3. **Plant к CareCalendar**: связь один ко многим с поддержкой каскадного удаления
4. **Plant к GrowthLogs**: хронологическая связь истории развития с экземпляром
