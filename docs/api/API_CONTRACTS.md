# API_CONTRACTS.md

Архитектурный стандарт взаимодействия между интерфейсным слоем (Flet UI) и слоем бизнес-логики (Services).

## 1. Стандарт возврата данных

Все методы сервисов возвращают кортеж из двух элементов:
```python
data_object, error_message = ServiceName.method_name(db_session, **params)
```
* **data_object**: экземпляр модели SQLAlchemy, список объектов, словарь или строка. Если операция завершилась ошибкой, всегда возвращается `None`.
* **error_message**: строковая переменная, содержащая текст ошибки на русском языке. Если операция успешна, возвращается `None`.
* **логика применения**: если переменная ошибки содержит текст, интерфейс обязан отобразить его пользователю через `ft.SnackBar` или диалоговое окно.

## 2. Спецификация сервисов

### 2.1. AuthService (Управление доступом)
* **login(db, email, password)**: проверяет учетные данные. В текущей версии используется прямое сравнение, в финальной — хеширование.
* **register(db, email, password, name)**: создает запись в таблице `users`. Проверяет email на уникальность перед созданием.

### 2.2. GigaChatService (Интеллектуальные функции)
* **identify_by_name(db, user_id, name)**: нормализует название через `PROMPT_NORMALIZE`. Используется для первичного поиска в справочнике.
* **get_passport_data(db, user_id, name)**: генерирует технические характеристики растения. Возвращает словарь для заполнения таблицы `plant_catalog`.
* **diagnose_plant(db, user_id, img_bytes)**: выполняет визуальный анализ через модель Max. Возвращает текстовый протокол лечения.
* **identify_plant_photo(db, user_id, img_bytes)**: распознает вид по фотографии. Возвращает готовый JSON-объект с параметрами ухода.
* **ask_agronomist(db, user_id, plant_info, query)**: текстовая консультация. Учитывает контекст конкретного экземпляра растения.

### 2.3. PlantService (Реестр растений)
* **get_or_create_catalog_item(db, ai_service, user_id, query)**: выполняет умный поиск в справочнике. Если вид не найден, автоматически запрашивает данные у ИИ и расширяет таблицу `plant_catalog`.
* **confirm_and_create_plant(db, user_id, catalog_data, custom_name, image_bytes, height)**: регистрирует растение в коллекции. Создает первую запись в журнале роста и планирует полив на текущую дату.
* **add_measurement(db, plant_id, height, note, image_bytes)**: добавляет запись в `growth_logs`. Обновляет статусное поле `status_text` в основной таблице растения.
* **archive_plant(db, plant_id, reason)**: переводит растение в неактивный статус. Удаляет все связанные будущие задачи из календаря ухода.
* **delete_plant_permanently(db, plant_id)**: полностью удаляет запись из базы данных. Стирает связанные файлы фотографий с физического носителя.

### 2.4. CareService (Планировщик ухода)
* **get_today_tasks(db, user_id)**: выбирает из базы невыполненные задачи на сегодня и просроченные. Работает только для активных (не архивных) растений.
* **complete_task(db, task_id)**: помечает задачу выполненной. Обновляет дату последнего полива в профиле растения и вызывает перегенерацию графика.
* **generate_full_schedule(db, plant_id, days_ahead)**: создает сетку задач на 30 дней вперед. Удаляет старые невыполненные задачи для предотвращения дублирования.

### 2.5. FileService (Работа с медиа)
* **process_and_save(image_bytes, subfolder)**: выполняет оптимизацию (ресайз, сжатие) и сохранение файла. Возвращает относительный путь для записи в БД, совместимый с механизмом ассетов Flet.

### 2.6. Аналитика (ReportService & ExportService)
* **collect_plant_data(db, plant_id)**: собирает агрегированную информацию о растении. Рассчитывает дельту роста и процент дисциплины ухода на основе выполненных задач.
* **create_plant_pdf(data)**: формирует PDF-файл. Использует библиотеку ReportLab и шрифты с поддержкой кириллицы из папки `assets/fonts`.
